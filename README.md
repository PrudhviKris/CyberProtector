# CyberGuard: Cyberbullying Detection with NLP & Machine Learning

🌐 **Live Demo:** [cyberprotector.onrender.com](https://cyberprotector.onrender.com) · [Analyse page](https://cyberprotector.onrender.com/verify) · [Model card](https://cyberprotector.onrender.com/model)

> Hosted on Render's free tier (baseline model only) — the first load may take ~30–50 s while the server wakes up.

### 🎬 Demo Video

https://github.com/user-attachments/assets/a687d2d8-9fa1-4828-aeff-1b202f9f04d9

CyberGuard is a full-stack web platform that detects cyberbullying in text. It combines a classical
**TF-IDF + Logistic Regression** model trained on about 17k labelled comments with a pretrained
**BERT transformer** (`unitary/toxic-bert`). Every result includes:

- a **bullying probability** and **severity level** (low / medium / high)
- scores for **six categories**: toxic, severe toxicity, obscene, threat, insult, identity hate
- an **explanation** that highlights the words that drove the decision

The platform also provides user accounts, saved history, batch CSV analysis, an admin analytics
dashboard, a help-desk ticket system and a REST API.

> v1 (the mini project) is preserved in [`legacy/`](legacy/). See [What changed from v1](#what-changed-from-v1).

---

## Features

| Area | What it does |
|---|---|
| **Analyze** | Paste text → verdict, probability gauge, category bars, highlighted trigger words |
| **Batch** | Upload `.csv` / `.txt` (up to 500 messages) → summary stats + downloadable results |
| **History** | Every signed-in analysis is saved; filter, paginate, export CSV |
| **Accounts** | Register / login (hashed passwords, CSRF protection). Public sign-ups are always regular users; only the owner can create admins |
| **Admin** | KPIs, 14-day trend, category / severity / source charts, recent flagged messages, ticket management, user list |
| **Help desk** | Tickets saved to the database and resolved by admins; includes helpline information |
| **REST API** | `POST /api/v1/analyze` with a per-user API key; single or batch requests |
| **Model card** | Live metrics, model comparison and confusion matrix generated by the training script |

## Architecture

```
            ┌──────────────── Flask app (cyberguard/) ────────────────┐
 Browser ──►│ routes: main · auth · admin · api   (Jinja2 templates)  │
 API client►│              │                                          │
            │              ▼                                          │
            │   ml/predictor.py  ─┬─► TF-IDF + LogReg (artifacts/baseline.joblib)
            │   (ensemble+explain)└─► unitary/toxic-bert (Hugging Face, 6 labels)
            │              │                                          │
            │              ▼                                          │
            │   SQLAlchemy models: User · AnalysisRecord · Ticket ──► SQLite / Postgres
            └─────────────────────────────────────────────────────────┘
```

**Pipeline:**
1. **Normalise** the text (`cyberguard/ml/text.py`): lowercase, strip URLs and @mentions, decode leetspeak and masking (`f*ck`, `$tupid`, `b1tch`), collapse repeated letters.
2. **Baseline:** TF-IDF word 1–2-grams plus character 3–5-grams, then Logistic Regression (C tuned by 5-fold CV).
3. **Transformer:** `toxic-bert` gives a sigmoid probability for each of the six Jigsaw labels.
4. **Ensemble:** `score = 0.4 · baseline + 0.6 · max(transformer)`. A message is flagged when `score ≥ 0.5`.
5. **Severity:** high when score ≥ 0.85 or the threat / severe-toxicity scores are high, medium when score ≥ 0.70, otherwise low.
6. **Explain:** word occlusion. Each distinct word is removed in turn, and the drop in log-odds is that word's influence.

If the transformer can't be loaded (offline, or `TRANSFORMER_MODEL=""`), the app automatically falls back to the baseline only.

## Results (held-out test set)

Dataset: 18,148 comments → **17,031 unique** after cleaning and de-duplication (65% bullying).
Stratified 80/20 split, so 13,624 comments for training and 3,407 for testing.

| Model | 5-fold CV F1 | Test F1 | Precision | Recall |
|---|---|---|---|---|
| SGDClassifier (modified Huber) | 0.938 ± 0.003 | 0.937 | 0.949 | 0.926 |
| LinearSVC | 0.939 ± 0.004 | 0.935 | 0.949 | 0.922 |
| RandomForest | 0.926 ± 0.004 | 0.929 | 0.935 | 0.924 |
| LogisticRegression (C=1) | 0.927 ± 0.004 | 0.927 | 0.953 | 0.903 |
| ComplementNB | 0.905 ± 0.007 | 0.907 | 0.907 | 0.906 |

**Deployed baseline (LogReg, C=30):** accuracy **92.1%**, precision **94.8%**, recall **92.3%**, F1 **0.935**, ROC-AUC **0.974**.
We chose Logistic Regression because it matches the best F1 while also giving calibrated probabilities and fast explanations.

**Why the ensemble helps:** *"I will find you and hurt you"* scores only 2% on the baseline, because it contains no abusive
vocabulary. The transformer recognises it as a **threat** (85%), so the ensemble flags it with high severity.

Plots are in `artifacts/model_comparison.png` and `artifacts/confusion_matrix.png`, and are also shown on the `/model` page.

## Getting started

```powershell
pip install -r requirements.txt
python training/train_baseline.py      # trains the model and writes artifacts/ (about 3 min)
python run.py                          # http://localhost:5000
```

The first run downloads `unitary/toxic-bert` (about 440 MB) to the Hugging Face cache.

### Admin access (owner only)

Anyone who registers on the website is a **regular user**. There is no way to become an admin from the website.
Admins can only be created by whoever controls the server:

- **On a hosting platform:** set `ADMIN_USERNAME`, `ADMIN_EMAIL` and `ADMIN_PASSWORD` (12+ characters) as
  environment variables in the platform's dashboard. On every start the app creates or updates that account as admin.
  Never put these values in the code or commit them.
- **With terminal access:** run `flask --app run create-admin`.

### Configuration (environment variables)

| Variable | Default | Purpose |
|---|---|---|
| `SECRET_KEY` | `dev-change-me` | Flask session signing. **Set this in production.** |
| `DATABASE_URL` | `sqlite:///instance/cyberguard.db` | Any SQLAlchemy URL (e.g. Postgres) |
| `TRANSFORMER_MODEL` | `unitary/toxic-bert` | HF model id or local path; `""` = baseline only |
| `THRESHOLD` | `0.5` | Bullying decision threshold |
| `BATCH_LIMIT` | `500` | Max messages per batch / API call |
| `ADMIN_USERNAME` / `ADMIN_EMAIL` / `ADMIN_PASSWORD` | unset | The owner's admin account (see above) |

## REST API

```bash
curl -X POST http://localhost:5000/api/v1/analyze \
  -H "X-API-Key: <your key from /account>" -H "Content-Type: application/json" \
  -d '{"text": "you are so stupid"}'
```

Send `{"texts": [...], "explain": false}` for batch requests. Full documentation is at `/api-docs`.

## Optional: fine-tune your own transformer

`training/train_transformer.py` fine-tunes DistilBERT on this project's dataset, using the same split as the baseline so the
numbers are directly comparable. Run it on a GPU (Google Colab T4: about 6 min), then point `TRANSFORMER_MODEL` at the output folder.

## What changed from v1

| v1 issue | v2 fix |
|---|---|
| `pd.concat([df, df])` before the train/test split, so the same rows appeared in both sets and accuracy was inflated | Duplicates removed first, then a stratified split and cross-validation on the training data only |
| App called `vectorizer.fit_transform()` on every input, re-fitting IDF weights on one sentence | A single fitted sklearn `Pipeline` is saved and loaded |
| Hard-coded absolute `C:\Users\...` paths | Paths are relative to the project, with env overrides |
| Binary output only | Probability, severity, six categories and an explanation |
| Help-desk form discarded submissions | Tickets are stored and managed in the admin panel |
| No accounts, history, API, tests or deployment | All added |

## Limitations & future work

- Sarcasm, reclaimed slurs, and code-mixed Hindi-English (Hinglish) text remain hard. A multilingual model such as `xlm-roberta` would help.
- Explanations come from the baseline model. Transformer-level attributions (Integrated Gradients / SHAP) would explain threats that use no abusive vocabulary.
- Possible next steps: a browser extension that scans pages, image/OCR analysis of memes, and active learning from help-desk "wrong prediction" reports.
